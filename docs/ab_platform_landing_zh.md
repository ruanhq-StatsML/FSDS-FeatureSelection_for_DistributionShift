# FSDS 软件在 A/B 实验平台的落地清单（CUPED 之外）

## 0. 结论

FSDS 的两条臂，把“批次指示变量”换成“实验组指示变量”或“灰度阶段指示变量”后，可以直接回答实验平台的问题：

| FSDS 原问题 | 换成实验变量后的问题 | 平台环节 |
| --- | --- | --- |
| 协变量漂移：P(X) 变了没有、哪些特征变了 | 分流是否真随机、哪个特征或模态块破坏了平衡 | 分流体检（SRM 的补全） |
| 概念漂移：E[Y\|X] 变了没有、哪些特征驱动 | 处理效应是否异质、哪些特征驱动异质 | 弱显著诊断、定向放量 |
| DR 伪结果 | 交叉拟合 AIPW 估计 ATE | 方差缩减（CUPED 的非线性、多协变量推广） |
| 分块 LOCO-MMD | 跨模态依赖漂移 | 多模态监控 |

前四件事已经实现在 `python/ab_diagnostics.py`，并用预埋场景验证过（见第 2 节）。第 3 节列出仓库里已有、改造后即可接入的其余能力；第 4 节是上线前必须补的工程缺口。

## 2. 已实现并验证的五件事

复现：

```bash
cd python
pip install numpy scipy pandas scikit-learn
python demo_ab_diagnostics.py
python -m pytest -q tests/test_ab_diagnostics.py
```

以下数字来自 `demo_ab_diagnostics.py` 的一次运行（seed 固定）。

### 2.1 分流体检：C2ST 随机化检验 + 特征定位

**问题**：SRM 只检验各组人数比例是否符合配置，检验不了各组人群构成是否相同。分流 SDK 的缓存、过滤条件或埋点 bug，会让某类用户在某一组里被系统性丢掉，而人数比例几乎不变。

**方法**：`split_balance_c2st`。在一半数据上训练 RF 分类器区分对照组和实验组，在另一半上计算 AUC。分类器已固定，因此置换留出集标签得到的零分布是有效的。再把留出集上每个特征（或每个模态块）整体置换，用 Brier 风险的上升量做定位。

**结果**：

| 场景 | AUC | p | 第一嫌疑特征 |
| --- | --- | --- | --- |
| 正常随机分流 | 0.488 | 0.874 | — |
| 实验组以 40% 概率丢掉 x2 < -0.5 的用户 | 0.557 | 0.002 | x2 |

**上线门槛**：p < 0.001 且连续两个批次告警时，暂停实验并审计分流链路；定位结果直接作为审计的起点。

### 2.2 CUPED 之外的方差缩减：交叉拟合 AIPW

**问题**：CUPED 只能用一个线性的实验前协变量。用户画像、历史行为和内容特征同时与指标相关、并且是非线性关系时，CUPED 吃不到这部分方差。

**方法**：`aipw_ate`。5 折交叉拟合 μ0(x)、μ1(x)，传入配置的流量比例作为倾向分 π，ATE 取 DR 伪结果的均值。随机实验中 π 已知，所以无论结果模型拟合得好不好，估计都无偏；结果模型拟合得越好，方差越小。

**结果**（真实 ATE = 0.05，n = 8000）：

| 估计量 | 点估计 | 标准误 | 方差 / 差均值方差 |
| --- | --- | --- | --- |
| 差均值 | +0.0084 | 0.0553 | 1.00 |
| CUPED（x0 作为实验前指标） | +0.0318 | 0.0319 | 0.33 |
| 交叉拟合 AIPW | +0.0390 | 0.0257 | 0.22 |

同样的样本量下，AIPW 的方差约为 CUPED 的 2/3，也就是达到同样功效所需的流量约为 CUPED 的 2/3。

**上线门槛**：协变量只能使用曝光前的特征，用曝光后的特征会把处理效应吸收掉；必须交叉拟合；需要同时报告差均值和 AIPW 两个估计，两者差异过大时人工复核。

### 2.3 弱显著诊断：异质性检验 + 驱动特征

**问题**：总体效应不显著时，可能是真的没有效应，也可能是不同子群的正负效应相互抵消。前一种应该停掉实验，后一种应该定向放量。

**方法**：`hte_drivers`。在一半数据上用 DR 伪结果拟合 τ(x)，在另一半上比较 τ̂(x) 与常数 ATE 的 PO-risk。差值显著为正，说明异质性是真实的，不是噪声。驱动特征用条件置换（X_j = ν_j(X_-j) + 置换残差）计算，避免把只是与真驱动特征相关的特征也算进去。

**结果**：预埋的真驱动特征 x3 稳定排在第一，但 n = 8000 时异质性检验 p = 0.11，处于检测边缘。这种情况应该如实报告“方向一致但证据不足”，不应据此直接定向全量。

**上线门槛**：用于定向放量的子群必须预注册，或者在新流量上复现；多指标、多子群同时检验时要做 FDR 校正。

### 2.4 灰度阶段对比：区分“流量构成变了”和“策略行为变了”

**问题**：灰度扩量后指标变化，可能是新放进来的流量人群不同，也可能是同一类用户对策略的反应变了。两种情况的处置方式完全不同。

**方法**：`stage_shift_report`。把灰度阶段作为指示变量：协变量臂检验人群构成，概念臂用估计的倾向分做 AIPW 和异质驱动排序。

**结果**（两个阶段流量构成相同，但第二阶段 E[Y|X] 新增了对 x3 的依赖）：协变量臂 AUC = 0.484、p = 0.916，不告警；概念臂 p < 1e-4，x3 排第一。

**处置规则**：只有协变量臂告警时，检查流量来源和分层；概念臂告警时，暂停扩量，并按驱动特征排查策略或模型。

### 2.5 多模态：跨模态依赖漂移

**问题**：逐模态做漂移检测，会漏掉“每个模态的边缘分布都没变、但模态之间的配对关系变了”这类漂移，例如图文错配或音画不同步。

**方法**：`block_loco_mmd`。对每个模态块同时计算两个量：只在该块上计算的 MMD（边缘），以及整体 MMD 减去去掉该块后的 MMD（LOCO）。

**结果**（文本、图像各 4 维，参考批次中两者正相关，新批次中负相关，边缘分布完全相同）：

| 块 | 边缘 MMD | LOCO MMD |
| --- | --- | --- |
| 全部 | 0.0232 | 0.0232 |
| text | 0.0000 | 0.0232 |
| image | 0.0000 | 0.0232 |

边缘 MMD 约为 0、LOCO MMD 显著为正，这就是跨模态依赖漂移的判据；逐模态监控在这个场景下完全检测不到。`split_balance_c2st` 和 `hte_drivers` 同样支持 `blocks` 参数，可以按模态块做分流体检和异质驱动排序。

## 3. 改造后即可接入的能力

1. **监控告警的 canary 压测**：把 `imageShiftLocalization.py` 里的 15 类腐蚀和 `adversarial_conceptdrift.py` 里的 5 类对抗扰动，作为预埋漂移注入影子流量，统计告警的检测功效、误报率和检测延迟。这一步是监控系统验收的事实基准。
2. **素材/封面 patch 级定位**：把 VAE 隐空间 + RF 域分类器 + 区域选择的流程拆成函数，接到多模态告警之后，输出可疑的图像区域。
3. **归因报告的非唯一性规范**：用 `fsds_nonuniqueness.py` 的路径分析，在报告中给出每个特征归因随加入顺序变化的区间，而不是一个唯一分解，避免归因被过度解读。
4. **弱重叠门槛**：用 `weakly_overlapped_benchmark.py` 标定重叠度下降到什么程度后，概念臂的排序不再可信；新人群和冷启动场景据此降级为只看协变量臂。
5. **模型敏感性报告**：通过 `model_registry_class.py` 替换 μ、π、τ 的模型，同时报告 AIPW 估计和驱动排序的稳定性（例如 top-K 的 Jaccard 相似度）。
6. **FDR 控制的漂移特征集合**：用 `SGShift.py` 的 knockoff 流程，在多指标、多特征的告警里控制错误发现率。
7. **作弊流量与流量污染**：README 中 ST-DBSCAN 聚类加双轴对比（与上一批次自身对比、与正常用户对比）的流程，可以用于识别刷量团伙对实验组的污染。
